Savings Tracker v2.0 - Application Presentation

Flask application overview, key features, workflow, and data model diagrams.

Slide 1: Overview

Savings Tracker v2.0 is a Flask-based enterprise web application for tracking procurement value across three initiative types:

  • Cost Savings
  • Rebates
  • Cost Avoidance

It modernizes data capture, approval workflows, reporting, and accountability for procurement teams.

Slide 2: Business Goals

  • Centralize initiative intake and lifecycle management
  • Standardize review and approval processes
  • Improve financial transparency and reporting accuracy
  • Maintain auditability for compliance and governance
  • Enable faster decision-making with dashboard analytics

Slide 3: Main Features

  • Role-based access control (Admin, Reviewer, User, Read-Only)
  • IIS Windows Authentication integration for SSO-style sign-in
  • Dashboard with statistics, filtering, and initiative status tracking
  • Separate forms for Cost Savings, Rebates, and Cost Avoidance
  • Facility allocation support with 100% total validation
  • Draft save and submit-for-review workflows
  • Initiative approve/reject actions
  • Audit logs for traceability of changes
  • File attachment tracking
  • REST API for CRUD and workflow actions
  • Email notification integration (Microsoft Graph)

Slide 4: Initiative Types Supported

Cost Savings

  • Baseline vs expected spend tracking
  • Automatic savings calculations
  • Contract and vendor metadata capture

Rebates

  • Rebate type and amount capture
  • Check date, payment type, and check number tracking
  • Rebate extraction/export support

Cost Avoidance

  • Original vs new quote analysis
  • Automatic avoidance calculations
  • Contract, PO, and baseline context capture

Slide 5: Workflow and Controls

  1. User creates or updates initiative data
  2. User saves as draft or submits for review
  3. Reviewer/Admin evaluates submission
  4. Reviewer/Admin approves or rejects
  5. System records actions in audit trail
  6. Stakeholders receive notification emails

Slide 6: Technology Stack

  • Backend: Flask 3.x, SQLAlchemy ORM, pyodbc
  • Database: Microsoft SQL Server
  • Frontend: Jinja templates, Bootstrap, JavaScript
  • Grid/UI: AG-Grid, responsive forms, status indicators
  • Auth: IIS Windows Authentication
  • Notifications: Microsoft Graph API
  • Deployment Target: IIS + FastCGI

Slide 7: API Capability Highlights

  • Authentication status and current user endpoints
  • Initiative listing with filtering and pagination
  • Initiative detail, delete, approve, and reject endpoints
  • Type-specific create/update endpoints: /api/cost-savings, /api/rebates, /api/cost-avoidance
  • Audit history and statistics endpoints

Slide 8: Operational Benefits

  • Better visibility into procurement impact
  • Stronger data integrity through validation rules
  • Clear ownership and review accountability
  • Faster reporting and export readiness
  • Improved compliance via audit history

Slide 9: Future Opportunities

  • Expanded analytics and KPI trend views
  • Additional export/report automation
  • Deeper role-based policy controls
  • Enhanced notification templates and routing
  • Extended integration with enterprise systems

Slide 10: Summary

Savings Tracker v2.0 provides a structured, secure, and scalable platform for tracking procurement initiatives from submission to approval, while improving reporting quality and governance.

Slide 12: Authentication and Authorization Flow

This flow shows how IIS handles Windows authentication, while the application and database enforce role-based authorization.

flowchart TD
    A[User Browser Request] --> B[IIS Site]
    B --> C{Windows Authentication Enabled?}
    C -->|No| D[Reject Request
401 Unauthorized]
    C -->|Yes| E[Validate AD Credentials
Kerberos or NTLM]
    E --> F{Identity Valid?}
    F -->|No| D
    F -->|Yes| G[Forward Request to Flask App
FastCGI wfastcgi]

    G --> H[App Resolves Current User
from IIS Identity]
    H --> I[Load or Auto-provision User]
    I --> J[(SQL Server users)]
    J --> K[(SQL Server user_roles)]

    H --> L[Route-level Auth Decorator
login_required]
    L --> M{User Active and Authenticated?}
    M -->|No| N[Redirect or 403]
    M -->|Yes| O[Permission Check
can_create, can_review, can_approve]
    O --> P{Role Allows Action?}
    P -->|No| Q[Return 403 Forbidden]
    P -->|Yes| R[Execute API or View Logic]

    R --> S[(SQL Server initiatives and related tables)]
    R --> T[(SQL Server audit_logs)]
    S --> U[Return Authorized Response]
    T --> U
